## Dead Ends — Do Not Retry

### Brokering credentials through ANTHROPIC_API_KEY environment variable
| Approach Tried | Why It Failed | Time Spent |
|----------------|---------------|------------|
| Passing lease token as `ANTHROPIC_API_KEY` | SDK validates API key client-side (prefix, length, checksum), rewrites forwarded value, and ignores `ANTHROPIC_BASE_URL` on validation failure — calls `api.anthropic.com` directly | ~2 hours |
| Using structurally valid fake API key | SDK checksum validation rejects identically-shaped random keys by pattern match | ~30 min |

**What to try instead**: Already implemented — OAuth credentials file path (`$HOME/.claude/.credentials.json`) bypasses client-side validation and honors base URL.

### Running lease shim inside sandbox container
| Approach Tried | Why It Failed | Time Spent |
|----------------|---------------|------------|
| Dual-listener lease shim in agent container | Violates A6 isolation guarantee — any credential in sandbox is accessible to agent, even on loopback | ~1 hour |
| Container-to-container credential passing | Creates credential flow through sandbox boundary, undermines security model | ~45 min |

**What to try instead**: Host-side credential management (already implemented) — credentials never enter container, only opaque lease tokens cross boundary.

### Pointing ANTHROPIC_BASE_URL to loopback address
| Approach Tried | Why It Failed | Time Spent |
|----------------|---------------|------------|
| `ANTHROPIC_BASE_URL=http://localhost:3004` | Claude CLI ignores loopback base URLs and connects directly to `api.anthropic.com` | ~20 min |
| `ANTHROPIC_BASE_URL=http://127.0.0.1:3004` | Same behavior — CLI treats loopback specially and bypasses custom base URL | ~10 min |

**What to try instead**: Use container service name in compose network (e.g., `http://egress-proxy:3004`) — already implemented and verified.

## Key Decisions

- **OAuth credential file over API key env var for sandboxed runs**: OAuth path bypasses SDK client-side validation and honors base URL byte-exact. API key path fails validation on structurally valid tokens. Trade-off: depends on undocumented credential file format.
  
- **Host-side credential reading with explicit opt-in**: Reading operator's keychain is sensitive operation requiring `LOOM_USE_HOST_CLAUDE_AUTH=1`. Trade-off: extra configuration step, but prevents silent privilege escalation.

- **Strip OAuth beta flags when using API key**: Proxy must remove `anthropic-beta: oauth-*` flags from requests when authenticating with API key to prevent protocol mismatch. Trade-off: header manipulation complexity, but enables API key fallback path.

- **Loopback-only control plane for credential injection**: Proxy's credential endpoint bound to 127.0.0.1, not published to container network. Trade-off: requires host-side credential push mechanism, but prevents sandbox from requesting credentials.

- **No credential logging or disk persistence in Loom code**: OAuth tokens held in memory only, refreshed from keychain on interval. Trade-off: requires keychain access, but minimizes credential exposure surface.

## Context for Future Sessions

**Critical security boundary**: The sandbox must never contain any credential. The current architecture maintains this through:
1. OAuth credentials file contains only per-run opaque lease token
2. Real OAuth token read from host keychain, never written to disk by Loom
3. Proxy's control plane bound to loopback, unreachable from sandbox network
4. `sandbox.test.ts` explicitly guards no credential-shaped env vars in container

**Credential flow verification**: When debugging authentication failures, check:
1. Request body for `authentication_error` vs `proxy_denied` — former is Anthropic's relayed error (check `request_id`), latter is proxy's
2. Fresh logs, not `--since`/`--tail` output — credential lease state can show stale
3. `NO_PROXY` must exempt both container name and proxy host, or CLI bypasses proxy

**API key fallback path**: Currently unverified. If anyone runs Loom with `ANTHROPIC_API_KEY` instead of OAuth, first check whether provider accepts requests with non-OAuth beta flags stripped. Unit test exists at header level; upstream acceptance is assumption.

**Undocumented dependency**: `.credentials.json` file format is not published SDK contract. Breaking change would surface as authentication failures in sandboxed runs. API key fallback exists as degradation path.

**Environment quirks**:
- `LOOM_SANDBOX_ENABLED=0` runs unsandboxed (genuinely less safe, not just less isolated — agent gets Runner's privileges and credentials)
- `LOOM_USE_HOST_CLAUDE_AUTH=1` required for OAuth token reading from keychain
- Sandbox must use container service name in `ANTHROPIC_BASE_URL`, never loopback
- Three migrations required: 0010 (kill-switch), 0011 (event log), 0012 (budget cap)
