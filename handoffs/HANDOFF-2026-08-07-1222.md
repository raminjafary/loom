## Key decisions

- A notification never carries tool arguments — deciding belongs against the exact
  argv on the approval card (§6 A3), not a lock screen. Two tests guard it.
- Notification delivery is best-effort and swallowed: a dead push service must not
  leave a run stuck in `awaiting_approval`.
- Backpressure *waits* rather than dropping events — the thread is the record of
  what the agent did.
- Attenuation refuses an unranked child model under a ranked parent (a typo would
  otherwise be the way past the tier check) but imposes nothing when the parent is
  itself unranked (§8's open-weight path).
- The child-run path is not on the contract. Its only legitimate caller is a
  Planner, which does not exist yet; a human starting a "child" by hand would mean
  nothing.

## Bugs found by driving the real thing, not by tests

1. The notification toggle read its config once on mount, so it never left
   "Notifications…" — config arrives when the session's `init()` resolves.
2. `listActiveByWorkspace` and `listNeedsAttention` had no `ORDER BY`. Both render
   as clickable rows re-polled every ~1.5s, so they reshuffled between polls and a
   click could land on a different run than the one aimed at.

That is five such bugs across sessions. Drive the UI and a real run before calling
anything done.
